# VS Code 预览与导出插件实现目标

在当前 Markview 仓库实现桌面 VS Code 的 统一插件 **Markview Preview & Export**（`szdytom.markview`），提供 Markdown 并排预览和无需打开预览的导出。复用 MVaaC、原生导出引擎和现有视觉素材，完成实际可运行的功能、测试、使用文档及 VSIX 打包流程。

本文件记录实现范围，已按最终单插件方案更新。实现和验证结果见 [验证记录](vscode-validation.md)；历史执行指令不代表当前提交授权。

## 执行方式

可使用以下指令启动实现：

```text
/goal 阅读 docs/vscode-implementation-goal.md，按其中的功能范围、技术决策、实施顺序和验收条件完成实现。复用现有组件和资产，完成测试与 VSIX 打包验证；不要提交、推送或发布。
```

先重新核对仓库状态和相关接口，再连续推进实现。常规技术选择可自行处理，不因阶段完成而停止。只有实际缺少必要输入或外部条件时才报告阻碍。不能用计划、模拟结果、空实现或未验证的构建产物代替完成。

遵循仓库 `AGENTS.md`，不要修改该文件。修改 Rust 源码前构建并备份当前 release 二进制；保持已有命令兼容。修改后运行相关测试，更新 changelog，并在完成时报告结果和无法验证的范围。

## 功能范围

| 模块 | 必须完成的行为 |
| --- | --- |
| 阅读预览 | 用户在 VS Code 原生编辑器编辑 Markdown，打开并排预览；预览更新当前编辑内容，包括未保存修改和无文件文档。 |
| 阅读交互 | 支持关闭预览、选择预览文字、复制和打开链接。 |
| 同步定位 | 支持双向滚动同步及开关；编辑器选中文字后，预览定位对应内容。 |
| 阅读主题 | 预览跟随 VS Code 明暗主题。 |
| 阅读配置 | 支持字号、栏宽、两端对齐、断词、段落缩进和代码块换行。 |
| 直接导出 | Markdown 编辑器右键提供 PDF 和 PNG 导出，使用默认导出模板并选择保存位置。 |
| 使用模板导出 | 依次选择模板、格式和保存位置。模板包含适用的内置模板、默认导出样式及自定义 `.mvss.toml` 文件。 |
| 导出输入 | 导出调用时的当前文本快照，支持未保存修改和无文件文档，不要求先保存 Markdown。 |
| 导出结果 | 完成后显示成功反馈，并在系统文件管理器中显示文件；用户取消时停止操作，失败时显示明确错误。 |
| 独立导出 | 安装统一插件后即可导出，不需要打开预览。 |
| 字体状态 | 显式展示模板字体在系统或插件本地缓存中的可用或缺失状态，并标明实际命中的字体。 |
| 字体下载 | 缺失字体提供下载入口，展示进度、完成反馈和失败重试。没有下载来源时明确提示安装或配置本地字体。 |

以下四条已经从需求中移除，不作为实现和验收条件：

- 预览选中文字后，编辑器定位对应源码。
- 普通文字单击不触发源码定位。
- 滚动同步不改变光标或选区。
- 预览选中后保持操作焦点，允许继续复制。

预览自身的选择和复制功能仍需完成。无需新增预览选区源码范围接口，也无需检测字符覆盖、缺字字形或 Emoji 合成。

首版验收范围是本地工作区的桌面 VS Code，提供 macOS、Windows、Linux 的构建和打包路径。远程工作区和浏览器版不作为首版验收条件；不得把远程机器字体报告为用户本地字体，也不得宣称未验证的远程功能已支持。

## 插件与共享代码

建议组织为：

```text
editors/
  vscode/
    src/preview/
    src/shared/
    src/export.ts
```

`vscode` 拥有预览、导出和字体管理命令，共用一套服务与缓存；只生成一个平台 VSIX。导出不要求打开预览，没有跨插件依赖。

共享代码负责模板目录、字体索引与下载缓存、导出任务及必要的数据协议。命令和 UI 的运行时所有权要明确，避免重复注册。插件 ID、目录细节和构建脚本按仓库约定决定，保持结构简单。

桌面本地扩展宿主负责文件访问、系统字体扫描、下载和原生进程；Webview 负责 viewer 与阅读界面。首版采用本地 UI 扩展宿主，以便字体来源与用户电脑一致。

## 预览技术方案

- Webview 挂载 `@markview/viewer`，不使用 `@markview/editor` 替换 VS Code 原生编辑器。
- 用 `TextDocument.getText()` 获取当前内容，监听文档变化调用 `setMarkdown()`。适度合并连续更新，保持原始换行与 UTF-16 坐标，不通过磁盘文件刷新预览。
- 预览绑定具体文档 URI，而不是每次操作都读取当前活动编辑器。处理文档切换、无文件文档首次保存、面板关闭及隐藏后的恢复。
- 消息携带文档身份和版本。快速编辑、切换文档和渐进布局时丢弃过期消息与几何结果。
- 复用 `@markview/scroll-sync` 的所有权和请求失效机制，新增 VS Code 适配层。原生编辑器只有可见源码范围和定位 API，采用源码位置跟随，不承诺像素级同步。防止两边滚动反馈循环，并支持关闭同步。
- 编辑器非空选区调用 `scrollToSource()`。Markdown 标记、图片、公式和折叠内容沿用当前源码导航语义，不要求两边选区完全等价。
- 将明暗主题变化传入 viewer。阅读设置使用现有 `fontSize`、`width`、`justify`、`hyphenate`、`paragraphIndent`；代码块换行使用高优先级 MVSS 的 `code_block` 和 `wrap` 规则。
- 加载字体字节并创建 `FontSet`。替换集合时保留所有仍需使用的字体，不因下载一个字体丢失已加载字体。
- 实现图片资源适配，正确解析本地相对路径与远程 URL。外部链接交给 VS Code 打开，文档内锚点沿用 viewer 导航，文件链接按文档位置解析。
- 打包 JS、WASM 和所需素材，使用 Webview 资源 URI 和 CSP；关闭面板时释放 viewer、订阅、资源任务与字体引用。

## 导出技术方案

新增统一原生导出入口，复用当前 PDF 导出与全文 PNG 分块拼接流程，不另写排版器。建议命令形态：

```text
markview export --format pdf --output result.pdf --stdin
markview export --format png --output result.png --stdin
```

这是待实现的接口。实现时补齐自定义模板输入、资源基准目录及字体目录参数，参数名称可按现有 CLI 约定调整。插件用参数数组启动进程，将原始 Markdown 通过 stdin 传入，不拼接 shell 命令。

现有 `markview pdf` 已有无窗口、无 GPU 的 PDF 路径。现有 `markview render` 输出指定画面尺寸的 PNG，不是全文长图入口。全文 PNG 应复用原生应用已有的布局、分块渲染、拼接和尺寸限制，将必要逻辑抽取到可独立调用的模块。

导出需要满足：

- PDF 保留矢量文字、嵌入字体和现有分页能力；PNG 覆盖全文，不是当前预览视口截图。
- 导出任务与预览独立，不要求创建隐藏 Webview，不改变当前预览配置。
- 默认导出采用打印样式。PDF 和 PNG 按现有原生导出语义使用 `pdf` destination，模板列表过滤不兼容的模板，自定义模板错误清晰可见。
- 模板按本次任务读取，不要求安装进全局模板目录；模板参数与规则尽量复用现有解析器。
- 已有文件的未保存修改以原文件目录解析资源。无文件文档优先使用其关联路径；没有路径时采用唯一工作区目录，多工作区时选择目录；确有相对资源且没有可用目录时请求资源基准目录。无相对资源时不额外询问。
- 开始时固定文本、模板和设置快照；导出中继续编辑不混入当前任务。
- 在临时输出完成后替换目标文件。取消或失败时清理临时文件，保留原有目标文件；覆盖由保存对话框确认。
- 保存对话框、模板选择和格式选择的取消均直接结束。运行中取消要停止原生任务并等待退出，不能仅隐藏进度条或丢弃返回消息。
- 将进度、退出状态和错误传回插件。进度协议采用最小必要设计，不依赖解析面向人的日志文案。
- 长图超过已有 PNG 尺寸限制时明确报错，提供降低比例或使用 PDF 的提示。
- VSIX 携带匹配平台的导出程序。提供构建、复制和校验流程，用户安装插件后无需自行安装 Rust 或编译 Markview。

## 字体管理技术方案

字体检查仅判断模板指定的字体家族是否存在于系统或插件缓存。使用 `get-system-fonts` 或等效 JS 目录扫描，并用 `fontkit` 读取字体内部名称、样式、字重和集合中的各个 face。不要依赖文件名匹配。

解析模板的字体定义及内置回退，按候选顺序选择可用字体。候选列表是回退关系，不要求全部候选都安装；界面显示实际命中的候选和来源。模板要求某个首选字体但实际使用回退时，可以标明回退状态。字体家族可用不等于所有字重或所有字符均完整，本目标不作这些保证。

- 扫描系统标准目录、插件缓存和用户配置的附加字体目录。
- 缓存路径、大小、修改时间和字体元数据，增量刷新；按需读取字体字节，不在每次编辑时全盘解析。
- 预览与导出共用确定的插件缓存位置。不要只把下载结果登记为可用而没有传给预览或导出后端。
- 下载由用户显式触发，使用模板 `[[font-family]]` 中的来源。没有声明来源时不猜测下载地址。
- 来源包含单独字体文件和归档文件时，沿用现有 MVSS 语义；可复用原生字体下载逻辑，或在共享模块实现等价支持。状态索引仍可使用 JS。
- 支持进度、失败重试和取消。临时下载验证成功后才进入缓存；失败不破坏已有字体。
- 复用现有校验和、归档路径约束及尺寸限制；保留模板提供的字体许可和来源信息。
- 下载完成后重新扫描并更新 UI，为预览创建包含所需字体的新 `FontSet`；后续导出传入相同字体缓存。

| 预览开关 | `assets/ui/eye.svg`、`assets/ui/eye-off.svg` |

| 其他平台图标 | `assets/icons/markview-{16,32,48,64,128,256,512,1024}.png`、`.ico`、`.icns` |

当前工作树没有 `editors/vscode/icon.png`。如实现开始时该文件已存在则复用，否则从已有品牌 PNG 生成插件打包副本，不将缺少这份副本当作阻碍。

功能 SVG 使用 `currentColor`。Webview 中采用内联 SVG 或 CSS mask 使颜色跟随主题，不能假设外部 `<img>` 会继承宿主文字颜色。优先使用 VS Code 原生菜单、设置、选择框和进度 UI，图标按钮提供文字提示和可访问名称。

## 实施顺序

1. 核对接口与工作树，准备工具链、构建基线、插件目录和打包脚本。
2. 完成可打开的预览，接入当前文本、图片、基础字体、选择复制、链接、主题和阅读设置。
3. 接入编辑器选区定位、双向滚动同步及开关，验证消息版本和快速文档切换。
4. 完成统一原生导出入口，接入 PDF 和全文 PNG，补齐文本与资源基准目录分离。
5. 完成无需预览的导出功能、默认导出、模板选择、保存、进度、取消和结果反馈。
6. 完成共享字体索引、状态列表、下载入口、进度、失败重试及重新加载。
7. 完成集成验证、素材打包、平台构建流程、使用文档和 VSIX 安装验证。

预览和导出可以先通过显式字体路径联调，完整目标仍要求完成字体管理；不要将临时字体配置作为最终交付。

## 验收条件

| 场景 | 通过条件 |
| --- | --- |
| 未保存编辑 | 修改已有 Markdown 后，预览与导出均使用内存内容，磁盘原文件保持不变。 |
| 无文件文档 | 新建 Markdown 可预览及导出；首次保存后文档绑定和相对资源正常。 |
| 预览生命周期 | 反复打开、关闭和切换文档无重复监听或持续后台任务，错误能被用户看到。 |
| 阅读交互 | 预览能够选择和复制文字；外部、相对文件和文档内链接按目标类型正确处理。 |
| 同步定位 | 两边滚动能跟随对应源码内容；关闭同步后停止跟随；快速编辑和切换时不会跳到旧文档。编辑器非空选区可定位预览。 |
| 主题与配置 | 明暗主题及全部六项阅读配置生效；代码换行开关有可观察差异。 |
| PDF | 长文档正确分页，文字可提取或选择，导出模板和字体生效，生成有效 PDF。 |
| PNG | 长文档首尾均出现在导出图中，跨块拼接没有截断；尺寸限制明确反馈。 |
| 资源路径 | 已有文件的未保存修改仍能导出相对图片；无文件文档使用选定的资源目录。 |
| 模板 | 默认、内置和自定义模板可用；格式不兼容或非法模板给出明确错误。 |
| 取消与失败 | 任意选择步骤取消不启动导出；运行中取消停止任务且不留下半成品；原有目标文件不被失败任务破坏。 |
| 文件反馈 | 成功后显示结果并定位系统文件管理器中的文件，定位失败与导出失败分别报告。 |
| 字体状态 | 系统字体、缓存字体和缺失字体可区分；按内部 family 名匹配；TTC 中的字体可识别；回退候选不被误判为全部必装。 |
| 字体下载 | 进度、完成、失败重试和取消可用；下载后预览和导出实际使用字体；无来源时提示合理。 |
| 独立安装 | 只安装统一 VSIX、不打开预览也能导出，菜单没有重复项。 |
| 打包 | VSIX 包含所需 JS、WASM、图标、模板和平台导出程序；在可用平台实际安装验证。其余平台提供 CI 构建与验证流程，不伪报本地验证。 |

测试以集成为主，覆盖文本输入、资源基准路径、自定义模板、PDF、全文 PNG、取消与字体缓存。字体测试使用受控 fixture，下载测试使用本地服务，不依赖真实 CDN。保留少量针对同步版本失效等状态逻辑的测试，不堆叠实现细节测试。

Rust 变更运行相关测试、格式检查和 lint；Web 变更运行相关类型检查、组件及浏览器测试；插件补齐类型检查、lint、扩展宿主集成测试和 VSIX 检查。具体命令写入工程脚本和使用文档。

本目标交付实现、测试、文档及本机可生成的 VSIX，不包含 commit、push、tag 或 Marketplace 发布。完成报告列明执行的测试、安装验证结果、产物路径和真实限制。
